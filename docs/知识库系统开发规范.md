# 知识库系统（Blog）开发技术方案

## 1. 概述
本系统旨在通过 Payload CMS 的 `Global` 设置，实现对知识库“列表页”、“详情页侧边栏”及“布局底部”的全局控制。支持运营人员自由搭建列表页板块并控制详情页的辅助功能。

## 2. 后台配置架构 (Payload CMS Global)

**Global Slug**: `knowledge-base-settings`

**板块 Blocks 字段规范 (Block: KnowledgeSection):**
- **模板选择**: Select (Template 1, 2, 3, 4)
- **标签标题**: Text (Localized) - 默认使用关联 `blog-tags` 的标题
- **板块介绍**: 标题, 描述, 按钮文本, 按钮链接 (Localized)
- **数据筛选**: `selectedTag` (Relationship: BlogTags) - 用于自动拉取该标签下的文章
- **展示项**: 发布时间, 标题, 作者 (Relationship), 阅读量, 封面, 分类名称

---

### Tab B: 详情页侧边栏 (Sidebar)
**全局逻辑**: 每个功能提供模板适用性勾选 (Applicable Templates: Select Multiple)

1. **TOC (目录)**: 开关。
2. **分享 (Share)**: 标题 (ML), 社交链接列表 (Icon + URL)。
3. **搜索 (Search)**: Placeholder 文案 (ML)。
4. **分类汇总**: 标题 (ML), 可选分类列表。
5. **推荐博文**: 标题 (ML), 手动选择博文列表。
6. **关注我们**: 标题 (ML), 社交链接列表。

---

### Tab C: 详情页底部 (Footer)
**全局逻辑**:  每个功能提供模板适用性勾选

1. **分类引导**: 选择特定分类，前端以 `·` 符号连接渲染。
2. **前后篇跳转**: 自动逻辑（基于 `publishedAt` 排序）。
3. **底部推荐**: 3个固定展示位。支持标题 (ML) + 手动精选。

## 4. 关键技术逻辑实现
### 4.1 数据拉取逻辑 (Server Side)
- **分类过滤**: 获取分类时必须强制条件 `{ type: { equals: 'blog' } }`。
- **板块联调**: 动态板块根据配置的 `selectedTag` 实时从 `Blogs` 集合获取前 N 篇文章（需考虑 Pagination 还是固定 Top 4）。

### 4.2 路由与跳转
- **按钮链接**: 板块按钮链接默认格式应为 `/blog?tag={slug}`。
- **分类连接**: 分类按钮链接默认格式应为 `/blog?category={slug}`

## 5. 待完善与增强功能建议 (Roadmap)

1. **阅读量统计**: `readCount` 字段需要一个后端原子递增的 API（建议使用 Payload 的 `hooks` 在访问时触发，或集成第三方统计）。
2. **自动推荐算法**: 详情页侧边栏的“推荐博文”除了手动选择，建议增加“同分类热门”自动拉取选项。
3. **目录自动生成**: `TOC` 功能需要前端根据正文 `h2`, `h3` 标签动态提取锚点。
4. **性能优化**: 列表页由于板块较多，建议针对文章封面图使用 `next/image` 的 `priority` 属性优化首屏板块。
